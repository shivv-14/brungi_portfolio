01Video Content Authenticator (VCA)Security · Cloud · 2026 — Present · Project

Problem

Videos are re-encoded, cropped and re-uploaded across social platforms, so a plain file hash cannot tell whether a clip is still the original.

Solution

An end-to-end authenticity system that signs videos at the source and verifies them anywhere, including after re-encoding.

Architecture & implementation

  • SHA-256 hashing for exact integrity, plus perceptual dHash analysis of frames (OpenCV) so verification survives re-encoded media.
  • Ed25519 digital signatures with a zero-trust design: keys are generated client-side and never leave the user.
  • FastAPI backend with SQLite, deployed on AWS EC2 behind HTTPS (Nginx, systemd), with AWS Cognito authentication.
  • A Chrome extension verifies videos in real time while browsing Instagram and LinkedIn.

Challenge & solution

Exact hashes break as soon as a platform re-encodes a file; combining a cryptographic hash with perceptual frame hashes keeps verification working on re-encoded copies.

My contribution

Built the system end to end: hashing and signature pipeline, FastAPI backend, AWS deployment and the Chrome extension.

Stack

FastAPIOpenCVSQLiteEd25519SHA-256 · dHashAWS EC2NginxsystemdCognitoChrome extension

06Native or Non-Native? Stylometric Writer ClassificationNLP · Research · 2026 · Personal research project

Problem

Can an anonymous English passage be classified as written by a native or non-native writer from style alone — and does it hold for writers the model has never seen?

Solution

A reproducible pipeline comparing handcrafted linguistic features with character n-grams, evaluated with writer-separated splits, plus a Streamlit app that explains each prediction.

Architecture & implementation

  • Handcrafted spaCy features (sentence length, vocabulary richness, function words, POS, punctuation) vs. character 3–5-gram TF-IDF.
  • Logistic Regression and calibrated Linear SVM with grouped cross-validation; writer-separated splits over 5 seeds.
  • Majority and length-only baselines, a document-level split to measure writer leakage, and a feature-group ablation.
  • pytest suite with CI on GitHub Actions; results tables are generated from results.csv, never typed by hand.

Data

W&I + LOCNESS (BEA-2019). ICNALE is supported as the recommended corpus. No synthetic data.

Limitations & next steps

In W&I + LOCNESS, only 50 native essays exist and the two groups wrote on different prompts, so topic is confounded with the label. The app is a research demo, not a judgement about any person.

Result

0.846macro-F1 ± 0.064 on unseen writers · ROC-AUC 0.895

My contribution

Designed the study, the data pipeline, models, experiments, tests and the app.

Stack

Pythonscikit-learnspaCyStreamlitpytestGitHub Actions

Native or non-native? A stylometric approach

INDEPENDENT STUDY · 2026

Question: can an anonymous English passage be classified as written by a native or non-native writer using only style signals — and does it still work on writers the model has never seen?

Method: handcrafted spaCy features (sentence length, vocabulary richness, function words, POS, punctuation) vs. character 3–5-gram TF-IDF; Logistic Regression and calibrated Linear SVM; writer-separated splits over 5 seeds, majority and length-only baselines, a leakage comparison and a feature ablation.

Finding: character n-grams (LR) reached 0.846 ± 0.064 macro-F1 and 0.895 ROC-AUC on unseen writers, against 0.688 for handcrafted features and 0.661 for a length-only baseline (W&I + LOCNESS corpus). Topic is confounded with the label in this corpus; limitations are documented in the repository.
